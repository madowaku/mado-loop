# MADO LOOP 1.0 Production Build

## Objective

Implement, verify, package, document, commit, and publish MADO LOOP 1.0.0 as a production Godot game-development orchestrator that routes implementation, creative, UI, sprite, integration, playtest, and P0-P5 proof work.

## Goal Kind

`specific`

## Current Tranche

Complete the final specification: source audit, production router, Godot tooling, creative/UI/sprite workflows and deterministic processors, AI Creole handoff, executable P0-P5 coverage, Windows clean-room installation, packaging, CI, documentation, final acceptance audit, coherent commits, and push when authorized.

## Non-Negotiable Constraints

- Windows 11 and Godot 4.7.2 are the primary release gate; Godot 4.6 is compatibility scope.
- Do not use Godot 4.8 development snapshots as the baseline or upgrade user projects for verification.
- Keep implicit skill invocation disabled and avoid unnecessary image/video analysis.
- Route optional Image Generation/specialist capabilities without auto-installing them or making them mandatory runtime dependencies.
- Distill external workflow principles unless deterministic runtime code truly requires vendoring.
- Preserve vendored MIT attribution and pin the complete upstream commit SHA.
- Do not select a root project license on the owner's behalf.
- Do not modify any game repository or the already installed user-wide prototype during repository implementation.
- Never treat missing mandatory dependencies or unverified mandatory checks as PASS.
- No secrets, force pushes, destructive Git commands, or signing configuration mutations.

## Stop Rule

Stop only when the acceptance audit passes, all safe local work is blocked, or continuing requires owner credentials/strategy. Do not stop after planning while a safe Worker task exists.
